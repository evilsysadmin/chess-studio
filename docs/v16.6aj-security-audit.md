# v16.6aj — auditoría de seguridad de aplicación

## Superficie pública deliberada

Solo quedan públicas estas rutas:

- `GET /api/health` — healthcheck/cold-start, sin datos de usuario.
- `POST /api/auth/register` — alta; rate limit y registro/invite configurables.
- `POST /api/auth/login` — login; rate limit.
- `POST /api/auth/forgot-password` — respuesta no enumerativa; rate limit.
- `POST /api/auth/reset-password` — token firmado de propósito específico; rate limit.

`/api/status` pasa a requerir JWT. El frontend autenticado manda ahora Bearer.

## Hardening añadido

- Los JWT de sesión nuevos llevan `purpose=session`.
- Un token `purpose=password_reset` ya no puede autenticarse como sesión.
- JWT de sesión legacy sin `purpose` siguen aceptándose durante la transición.
- Auth falla cerrado con `503` si no puede comprobar que la cuenta sigue existiendo.
- Los endpoints `/api/admin/*` usan una única dependencia `require_admin`.
- `ADMIN_USERNAMES="*"` provoca fallo de arranque en producción; sigue permitido en desarrollo local.
- Comparación de M2M API keys con `hmac.compare_digest`.
- CORS limitado a métodos y headers realmente usados.
- Baseline de cabeceras defensivas: nosniff, DENY frame, no-referrer, Permissions-Policy y CSP de API.
- HSTS en entorno production/prod.
- Peticiones con Content-Length declarado superior a 1 MiB se rechazan con 413.

## Anti-regresión

`scripts/api_surface_gate.py` analiza estáticamente las rutas FastAPI. Cualquier ruta nueva fuera de la allowlist pública debe declarar autenticación; toda `/api/admin/*` debe declarar `Depends(require_admin)`. El gate corre tanto en `make security` como en GitHub CI.
