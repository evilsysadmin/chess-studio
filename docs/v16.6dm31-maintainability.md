# v16.6dm31 · mantenibilidad

## Objetivo
Release sin features: reducir deuda y reforzar contratos.

## Refactor backend
`backend-python/main.py` baja de 899 a ~587 líneas. Las rutas de partidas y análisis viven en `game_api.py` mediante un `APIRouter` construido con las dependencias de auth/rate-limit inyectadas. Los paths y contratos HTTP se mantienen.

## Cancelaciones
Sólo `win`, `draw` y `loss` habilitan progreso competitivo. Una salida voluntaria de una partida competitiva ya iniciada se convierte explícitamente en `loss` (forfeit/resignation), por lo que sí penaliza rating, racha y estadísticas. `cancelled` queda reservado a una partida sin primer movimiento o a contextos no competitivos; `retired` sigue siendo una retirada propia de Combat/special runs y no se transforma en una derrota casual artificial.

## Tests
Se elimina `aiPlayerPortraitWiring.test.js`, que inspeccionaba strings de `App.jsx`/`InsightsScreen.jsx`; su contrato real de cooldown pasa al test unitario de `aiPlayerPortrait`. `test_suite_audit.mjs` fija un techo de 15 source-reading contract tests: la deuda puede bajar, no crecer.

## Runtime local
`make python-check` exige Python >= 3.10 antes de crear/actualizar el entorno. `.python-version` sigue marcando 3.13 como runtime de referencia.
