# v16.6dm1 · Historial de ciclo de vida

## Objetivo

Registrar actividad real del usuario, no inferirla sólo de partidas archivadas.

## Contrato

- `started`, `cancelled`, `finished` se guardan en `chess-study-game-activity`.
- Se deduplica por `gameId + state`.
- Un juego finalizado no puede registrar después una cancelación espuria al volver desde resultados.
- Mongo sincroniza la clave como parte del perfil.
- Admin prefiere el journal; perfiles antiguos conservan fallback al historial final.
- Los nombres de modo viven en `gameModes.js`.

## Combat Chess

Cada batalla genera un id de actividad al arrancar y lo persiste en el snapshot de sesión para mantener continuidad durante la batalla. Campaña, Torre, Torre infinita y Batalla libre quedan diferenciadas.
