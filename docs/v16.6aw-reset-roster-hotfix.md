# v16.6aw · Hotfix reset global del ejército

Micro-iteración sobre v16.6av para corregir una regresión detectada por `resetProgress.test.js`.

## Problema

`resetAllProgress()` llamaba a `resetRoster()`. Desde que cada unidad de Combate nace con una identidad aleatoria, `resetRoster()` elimina el roster anterior pero crea y persiste inmediatamente uno nuevo. Por eso `chess-study-combat-roster` volvía a existir justo después del reset global.

## Corrección

- `resetRoster({ persist: true })` conserva por defecto el comportamiento del reset específico de Combate: crea un destacamento limpio con identidades nuevas y lo persiste.
- `resetAllProgress()` usa `resetRoster({ persist: false })`, de modo que el reset global deja la clave realmente ausente antes de sincronizar el perfil vacío con el backend.
- Se añaden regresiones para ambos contratos.

No cambia reglas de juego, progresión, nombres, metamorfosis ni dependencias.
