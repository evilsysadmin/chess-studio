# V16.5 — saneamiento de reglas, recuperación y audio

Esta versión no intenta añadir otra capa de confeti: endurece sistemas que ya existían y elimina varias contradicciones entre lo que la UI prometía y lo que las reglas hacían de verdad.

## Gate de Combate / Roguelike

Reglas que quedan explícitas y protegidas por tests:

- **Fuerza = ofensiva.** Aumentar Fuerza mejora la probabilidad de conectar una captura; no vuelve a la pieza más difícil de capturar.
- **Velocidad = evasión.** Aumentar Velocidad mejora la defensa; no aumenta la puntería al atacar.
- Los stats base conservan arquetipos: la Velocidad innata cuenta de verdad (un caballo V30 es más evasivo que una torre V6). El color no altera probabilidades.
- El porcentaje normal queda acotado al 20–90 %. El rey siempre conecta y nunca esquiva.
- Una captura que **saca al propio rey de jaque** conecta al 100 %: un fallo no puede fabricar una posición ilegal.
- Una captura que **da jaque mate** también conecta al 100 % y la UI muestra ese mismo 100 % antes de confirmar.
- Un fallo de captura consume el turno y deja el tablero intacto. Se limpian los derechos de en-passant efímeros y avanzan los contadores FEN de forma coherente.
- Un fallo no puede crear un mate/ahogado fantasma únicamente por pasar el turno sin mover: en ese caso el golpe se fuerza. En cambio, una **tabla legítima por 50 jugadas** sí puede alcanzarse mediante un turno fallido.
- **Fuego concentrado**: sólo los fallos consecutivos contra el mismo objetivo acumulan bono. Un acierto, cambiar de blanco o una jugada no capturadora lo reinician.
- La triple repetición de Combate se cuenta externamente porque reconstruir `Chess` desde FEN pierde el historial interno de chess.js.

### Veteranos y bajas

El slot de una pieza no desaparece físicamente del ajedrez para siempre. Lo que se pierde es la **veteranía**:

1. Una pieza con progreso muere y queda recuperable hasta la siguiente batalla.
2. Si se revive a tiempo, cuesta XP de combate y conserva la mitad de sus puntos comprados.
3. Si se empieza otra batalla sin revivirla, se borra ese progreso y el slot reaparece como una pieza nueva de nivel 1.
4. Una pieza que murió sin ninguna mejora comprada no genera una falsa deuda de resurrección: no había progreso que rescatar.

## Roguelike

- Cada intento recibe una `seed` persistente.
- El modificador de cada piso se deriva de `seed + floor`; refrescar o remontar React no rerollean el encuentro.
- La previsión del piso siguiente usa exactamente el mismo cálculo que el encuentro real.
- El estado persistente distingue `battle`, `fighting` y `cleared`.
- La victoria se marca `cleared` **antes** del intermedio, impidiendo repetir un piso ganado para farmear recompensas.
- Sólo una victoria permite avanzar. Tablas, derrota y retirada terminan el intento.
- Si la pestaña desaparece durante `fighting`, el intento se considera interrumpida en vez de regalar un restart con nuevas tiradas. No se inventan bajas que nunca llegaron a persistirse.
- La dificultad aumenta de forma monótona y tiene tope 95; en pisos altos la presión adicional viene también del material/modificador.

Limitación consciente: la CPU sigue escogiendo su jugada con valoración ajedrecística normal; todavía no rerankea candidatos según la probabilidad de impacto propia de Combate. Es una mejora futura posible, no una incoherencia de reglas.

## Rating de torneo

Torneo usa el mismo score ELO que una partida competitiva normal:

- victoria = 1;
- tablas = 0.5;
- derrota = 0.

Por tanto una derrota de torneo baja rating salvo que el jugador ya esté en el piso absoluto de 400. No se concede un segundo bonus ELO por ganar el torneo completo: cada partida ya puntuó una vez.

## Email y recuperación de contraseña

La UI de registro solicita email para altas nuevas. Cuentas antiguas pueden añadirlo o editarlo desde **Mi cuenta** confirmando la contraseña actual.

Flujo de recuperación:

1. `POST /api/auth/forgot-password` recibe email y siempre devuelve una respuesta genérica, exista o no la cuenta.
2. Si existe, genera un JWT de propósito `password_reset` válido durante 30 minutos.
3. El token incorpora una huella del hash actual de contraseña: tras cambiar la contraseña, el mismo enlace deja de ser válido aunque aún no haya caducado.
4. `POST /api/auth/reset-password` valida token + huella y entrega una sesión normal tras el cambio.

Producción usa la API HTTP de **Resend** mediante biblioteca estándar, sin meter SDK ni SMTP en el backend. Variables:

- `RESEND_API_KEY`: secreta y necesaria para envío real.
- `PASSWORD_RESET_URL`: URL pública exacta del frontend, incluyendo el base path de GitHub Pages.
- `PASSWORD_RESET_FROM`: remitente verificado de Resend para envío real a usuarios arbitrarios.

En desarrollo, si no hay `RESEND_API_KEY`, el enlace se escribe en logs para poder probar el flujo local completo.

## VOICE / TTS

- `VOICE` vive dentro de Game Chat y está OFF por defecto.
- Sólo habla entradas reales del transcript; no narra capturas/jaques genéricos.
- El primer preview se dispara síncronamente desde el click del usuario para conservar el gesto de desbloqueo de Safari/iOS.
- Si Chromium acepta `speak()` pero no dispara `onstart`, hay watchdog, `resume()` y reintento sin voz fijada.
- Mientras habla, la música hace ducking y después recupera su volumen.

La Web Speech API depende finalmente de que navegador/SO ofrezcan un motor TTS. Si un Linux no tiene ninguna voz operativa, la app no descarga por detrás un modelo pesado ni manda el texto a un tercero.

## Audio

El mini-Winamp añade volumen de música 0–100, persistente en el perfil. FX conserva ON/OFF independiente. El catálogo queda en **36 temas**, añadiendo cuatro piezas de pulso más vivo para que la sesión no sea siempre contemplativa:

- Cairo · farol rojo 01:37
- Beirut · taxi nocturno 02:18
- Tánger · mesa roja
- Estambul · tavla 03:08

## Navegación y pieza clavada

- ESC y clic derecho comparten una pila global de navegación “atrás”. Sólo actúa el manejador superior.
- El clic derecho no se intercepta dentro de inputs, textareas ni elementos editables.
- Durante partidas/batallas activas no se usa para abandonar accidentalmente.
- Si se selecciona una pieza que no tiene jugadas porque está absolutamente clavada contra su rey, la UI lo explica. El caballo `c6` bajo `Bb5` con rey `e8` era un caso legal de clavada, no un fallo de chess.js.
