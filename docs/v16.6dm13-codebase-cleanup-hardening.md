# v16.6dm13 · codebase cleanup & hardening

## Objetivo

Reducir deuda acumulada sin cambiar reglas de ajedrez, IA ni mecánicas de juego. La pasada combina correcciones funcionales pequeñas con eliminación conservadora de código que ya no tenía consumidores.

## Reinicio de progreso

- `profileKeys.js` separa explícitamente `PROFILE_PROGRESS_KEYS` y `PROFILE_PREFERENCE_KEYS`.
- `resetAllProgress()` borra desde esa única fuente de verdad en vez de mantener una segunda lista manual.
- Se corrige el olvido de racha diaria, journal de actividad y claves legacy de progreso.
- Se preservan login, partida activa y preferencias puras como audio/voz, tutoriales vistos y modo zen.
- Los presets de despliegue y el tema de tablero sí se reinician: dependen del roster/carrera que acaba de volver a cero.

## Recuperación y backend

- Se añade un ErrorBoundary exterior a `App`, de modo que un fallo durante la propia inicialización ya no queda fuera del boundary recuperable interior.
- El fallback raíz conserva el savegame y ofrece recargar/recuperar, nunca borra una sesión activa por el mero error de render.
- Se elimina `GET /api/games/{id}/moves`, sin consumidores en frontend ni tests.
- `/api/games/{id}/hint` gana pruebas backend de éxito, turno incorrecto, partida terminada y ausencia de sugerencia.
- `play_move` deja de capturar cualquier `Exception` como “Movimiento ilegal”: fallos internos inesperados llegan al middleware seguro de 500 con request id.

## Limpieza segura

- Se retiran imports React redundantes bajo el runtime JSX automático de Vite y otros imports realmente muertos.
- Se elimina el sistema legacy de temporadas/runs de `metaProgress.js`, manteniendo sólo las derivaciones todavía consumidas.
- Se retiran helpers/resetters sin consumidores, APIs de audio obsoletas, dos iconos PWA no referenciados y selectores CSS antiguos sin referencias.
- El README deja de anunciar el endpoint `/moves` retirado.
- Los scripts legacy de integración no se borran todavía porque siguen formando parte de las comprobaciones del repositorio; su retirada requiere un refactor explícito del gate.

## Tests y coverage

- Los tests de reset usan la misma lista canónica de claves que producción, evitando que código y test vuelvan a quedarse desfasados juntos.
- Se elimina una duplicación de `_presence_summary`.
- El include informativo de V8 se amplía a continuidad, reconexión, guardado, Home/Admin, perfil/reset, actividad/carrera y otras utilidades recientes.
- No se añaden thresholds de coverage en esta release.

## No cambia

- Reglas de ajedrez.
- Dificultad/IA.
- Persistencia de partidas activas.
- Cadencia de presencia/telemetría.
