# V16.6f — CI saneado + “Así juegas” unificado

## Frontend CI

- El entorno de Vitest en Node dispone ahora de `localStorage` y `sessionStorage` independientes.
- El test de pieza bloqueada usa una posición realmente bloqueada (`a3` ocupa la casilla frontal y `b3` queda libre).
- `puzzles.test.js` entra en el gate crítico para impedir que vuelva a colarse un puzzle con posición inicial imposible.

## Backend CI

- Los tests que verifican endpoints anónimos usan `raw_client`, no el wrapper histórico que añade Bearer automáticamente.
- El test de mate acepta la puntuación finita con distancia al mate (`99999`, etc.) en vez de exigir que toda evaluación decisiva sea exactamente el sentinel `100000`.
- El mock de `create_user` acepta el nuevo argumento `email=`.

Los cambios corrigen tests desfasados; no se relaja autenticación ni se cambia la evaluación de la IA para hacerlos pasar.

## Deploy

`static.yml` ya no compite en paralelo con CI. Se activa al completar el workflow `CI`, despliega solo si:

- la ejecución fue un `push`;
- la rama era `main`;
- CI terminó con `success`.

Además hace checkout de `workflow_run.head_sha`, de modo que se construye exactamente el commit que pasó los tests. `workflow_dispatch` sigue disponible para despliegue manual.

## Así juegas

Se elimina la entrada separada “Centro de operaciones”. Toda la analítica y entrenamiento personal queda bajo una única entrada principal **Así juegas**, con dos subpáginas internas:

- **Diagnóstico**: roast, coaching, estadísticas agregadas, modos, aperturas, rivalidad, incidentes tácticos, peor jugada y evolución de rating.
- **Expediente**: temporada, informe semanal, entrenamiento personalizado, conversión/defensa, Hall of Fame/Shame, runs, ritmo, aperturas avanzadas, evolución, perfil automático, mapa de aperturas, tableros, cementerio y crónica de rivalidad.

No se duplican datos ni se inventan nuevas métricas: se reutilizan los mismos stores e históricos ya existentes.
