## Aviso de versión nueva

Hasta dm26 el backend recibía la release del cliente y Admin podía clasificarla, pero el propio usuario no recibía un aviso preventivo. dm27 añade `frontend/public/release.json` y una comprobación cliente:

- al montar la aplicación autenticada;
- cada 5 minutos;
- al volver a poner la pestaña en primer plano;
- `cache: no-store` + query de cache-busting;
- fallo silencioso si no hay red o el manifiesto es inválido.

Si la release publicada difiere de `APP_RELEASE`, aparece un aviso compacto. Fuera de una partida ofrece `Actualizar`; durante una partida activa no ofrece recarga y explica que se actualice al terminar. Fuera del tablero, `Ahora no` silencia esa release durante la pestaña actual. En una partida, `Después` oculta el aviso sólo durante esa partida; al salir del tablero vuelve a estar disponible la actualización.

Importante: una pestaña que ya ejecutaba dm26 antes de desplegar dm27 no contiene este checker, así que no puede descubrir dm27 mágicamente. Tras cargar dm27 una vez, los siguientes deploys sí se detectan sin intervención.

El release consistency gate valida también que `release.json`, `RELEASE.txt` y `APP_RELEASE` sean idénticos para impedir falsos avisos por un deploy mal versionado.
