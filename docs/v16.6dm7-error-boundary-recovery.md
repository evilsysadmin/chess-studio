# v16.6dm7 · fallback recuperable de partida

## Objetivo

Un error de render dentro de la aplicación no debe expulsar al jugador de una partida activa como primera reacción.

## Comportamiento

- `ErrorBoundary` conserva el snapshot de sesión y ofrece **Recuperar partida** como acción principal cuando existe una partida activa.
- La recuperación reutiliza el restaurador común de v16.6dm6: vuelve a pedir el estado real al backend y reconstruye Partida rápida/Práctica/variantes/reloj o Torneo según corresponda.
- Combat Chess y Roguelike también son recuperables: el fallback remonta la pantalla y el controlador rehidrata la batalla desde su snapshot efímero de `combatSession`/`sessionStorage`.
- Si el error ocurre justo al entrar al tablero, antes de que el effect haya escrito el snapshot, se usa el `gameId` vivo en React como red de seguridad adicional.
- Un fallo de red durante la recuperación no borra el savegame: el fallback permanece abierto y permite reintentar.
- **Volver al menú** sigue disponible como salida secundaria y tampoco destruye la sesión activa; el jugador puede continuarla después desde el menú.
- El fallback deja de presentar un error terminal: visual y texto se orientan a recuperación, manteniendo un estado claro para errores realmente irrecuperables.

## Cobertura

El contract-test de continuidad comprueba el wiring `ErrorBoundary -> recoverSessionFromBoundary -> restoreActiveSession`, las rutas normal/torneo y la presencia de las dos acciones del fallback.
