# v16.6dm29b · contrato verificable de “Así te ve la CPU”

## Problema

Un modelo remoto podía obedecer mal el prompt y producir texto formal, teatral o directamente ajeno a las estadísticas del jugador. El fallback existía para fallos de transporte, pero una respuesta HTTP válida del modelo se aceptaba con una comprobación de grounding demasiado general.

## Solución

`player_portrait` pasa por una barrera específica en FastAPI antes de considerarse éxito Cloudflare. Se exige:

- exactamente tres frases compactas;
- ausencia de saludos, despedidas, tratamiento de usted, cartas, Markdown y prefijos de narrador;
- al menos un ancla verificable del dossier (cifra real o nombre literal de apertura);
- tercera frase accionable para las próximas partidas;
- después se conserva la validación general de conceptos ajedrecísticos contra HECHOS.

Un incumplimiento produce `portrait_contract_rejected:<motivo>`, activa el fallback local y no confirma el cooldown manual.

## Aislamiento local

El cache schema 6 guarda `identityScope` y sólo devuelve el retrato cuando coincide con la identidad autenticada actual. El cambio de schema invalida cualquier retrato dm29/dm29a ya guardado.

## Correlación técnica

Las llamadas narrativas incluyen un `X-Request-ID` generado en frontend. FastAPI usa el mismo identificador en su middleware/log y lo pasa, como metadato firmado fuera de HECHOS, al Worker. El Worker lo incorpora únicamente a logs técnicos de éxito/error. No se registran prompt, dossier, username, JWT, FEN ni texto generado.
