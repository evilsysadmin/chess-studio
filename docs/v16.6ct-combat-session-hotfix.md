# v16.6ct · hotfix de retorno inesperado a Setup en Combat Chess

Síntoma observado en dev Docker Compose:
- una batalla Combat activa vuelve de golpe a la pantalla de preparación/setup.

Hallazgos:
- v16.6cs introdujo un `useLayoutEffect` en `CombatScreen` que actualizaba estado del `App`
  durante la transición Setup -> Battle. En desarrollo, React StrictMode duplica ciclos de efectos
  y no es una frontera adecuada para la máquina de estado del combate.
- Roguelike/Campaign usaba `combatSessionActive` (estado React) como proxy de la sesión real. Ese
  booleano puede quedar desfasado tras remount/HMR. Si se conservaba `true` pero `loadCombatSession`
  devolvía null, `CombatScreen` se montaba como `setup`.
- `saveCombatSession()` podía propagar una excepción de `sessionStorage.setItem`, rompiendo el flujo
  del evento aunque la partida React siguiera viva.

Correcciones:
- `useLayoutEffect` -> `useEffect` pasivo para el cambio puramente visual del layout global.
- Campaign/Tower verifican `hasCombatSession(id)` como fuente real durante `phase=fighting`.
- Snapshot redundante en memoria para remount/HMR en la misma carga de página.
- `saveCombatSession` queda protegido: un fallo de storage no rompe la partida y usa el espejo RAM.
- Watchdog durante `phase=battle`: si falta snapshot, vuelve a checkpointarlo.
- En roguelike se bloquea cualquier transición silenciosa `battle -> setup`; la salida válida es retirar.
