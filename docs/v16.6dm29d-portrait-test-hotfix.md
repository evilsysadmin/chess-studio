# v16.6dm29d · Hotfix del contrato de cooldown del retrato AI

El comportamiento de producción de dm29c era correcto, pero el test estático `aiPlayerPortraitWiring.test.js` seguía buscando literalmente `markPlayerPortraitManualRefresh()` después de que la llamada pasara a recibir `identityScope`.

El contrato actualizado comprueba el orden semántico relevante:

1. existe el guard `if (!text)` para respuesta remota vacía/fallback;
2. el commit del cooldown manual ocurre después de ese guard y dentro del éxito manual;
3. no se marca el cooldown en la rama de fallback;
4. `requestFreshPortrait()` por sí mismo no consume el cooldown.

No cambia código productivo del retrato AI.
