# v16.6dm6 · continuidad de partida entre deploys

## Objetivo

Un deploy del frontend no debe expulsar al jugador al Home ni perder el contexto de una partida que ya estaba en curso.

## Cambios

- Snapshot local versionado de la sesión activa: ruta, game id, tablero/historial recibido, contexto cliente, modo práctica y control de tiempo.
- Restauración automática desde el savegame persistente del backend al recargar una partida normal.
- La misma continuidad cubre partidas de Torneo, que antes no tenían descriptor de sesión activo.
- Un `vite:preloadError` o un error típico de chunk dinámico viejo fuerza un único refresh controlado para cargar los assets del release nuevo.
- Cooldown de 15 s evita bucles de refresh si el problema real es de red y no un deploy.
- Los fallos transitorios conservan el snapshot para reintentar; un 403/404 limpia únicamente una partida realmente irrecuperable.
- Logout/cambio de identidad elimina también el snapshot para que nunca se herede entre usuarios.
- Tutorial de Partida rápida actualizado a la UI simplificada: dificultad primero; color/reloj/series bajo Ajustes; reglas especiales un nivel más abajo.

## Fuente de verdad

El snapshot del navegador no sustituye Mongo. El backend sigue reconstruyendo la partida desde el savegame persistente; el snapshot conserva el contexto de interfaz necesario para volver exactamente al modo que estaba jugando el usuario.
