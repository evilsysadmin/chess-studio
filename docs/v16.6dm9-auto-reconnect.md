# v16.6dm9 · auto-reconnect de partida activa

## Objetivo

Cuando el navegador pierde conectividad durante una partida normal, de práctica, variante o Torneo, la vuelta de red no obliga al jugador a salir, recargar ni pulsar Continuar. La app resincroniza automáticamente el tablero abierto contra el backend.

## Flujo

1. El evento `offline` marca que la sesión necesita reconciliación.
2. Al recibir `online`, si sigue abierta una partida recuperable, el badge pasa a **Guardando…**.
3. Se pide `GET /games/:id` y Mongo/backend actúa como fuente autoritativa.
4. Si la respuesta corresponde al mismo `gameId`, se reemplaza el objeto React por la copia confirmada.
5. El snapshot local de continuidad se reescribe mediante el flujo existente de `activeGameSession`; sólo entonces el badge vuelve a **Guardado**.
6. Si la petición falla, se conserva el tablero confirmado y el snapshot local, el badge queda en **Error al guardar** y un futuro `online` puede reintentarlo.

## Seguridad contra carreras

Si el jugador sale de la partida o cambia de pantalla mientras el `GET` de reconciliación está en vuelo, la respuesta tardía se descarta. No puede reabrir ni sobrescribir una partida que el usuario ya abandonó.

## Combat Chess / Roguelike

No hacen una reconciliación backend ficticia: su batalla activa sigue persistiendo en `combatSession/sessionStorage`. El badge de conectividad vuelve automáticamente a su estado de persistencia local cuando el navegador recupera red.
